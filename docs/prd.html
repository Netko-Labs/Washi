Washi

A team workspace of living pages. People and Washi, the agent, write them together; Washi keeps them true, and the team's work — tickets, metrics, the weekly review — lives on the same pages.

v1 · 2026-10-21supersedes washi.html · spec.html · server.html · features.mdteams firstself-hosted

30-second version

  1. One product. Living pages a small team and its agent keep together. Not a chat app, not a code reviewer, not a blank canvas, not a personal vault.
  2. Both write, as equals. Type into a page or ask for one. Washi's edits land marked as its own and undo as one change; only what leaves the workspace stops at the desk.
  3. One runtime, two hosts. The studio (hosted, a team server) and the desktop (embedded, offline, one person) serve the same appRouter. Mode is asserted once at boot.
  4. Two planes. Postgres holds identity only. One SQLite file per workspace holds everything else, same code hosted and local. This is C1, and it is what makes local mode a redeployment instead of a second product.
  5. Pages are WSX. Inert data from a closed registry: literal props, four enums, a closed expr grammar, validated before persist and before render. Nothing in a page executes.
  6. Tables are Notion databases with history. Every row is a page; every write is appended to a change log charts replay day by day. The team's week — backlog, roadmap, wiki, ideas, review — is a starter on top, not a built-in model.
  7. Next is the golden flow. Investigations, tickets with keys, metrics with targets, a GitHub app and workflow rules — twelve PRs, in §08.
01

What Washi is

Washi was a designed canvas, a Notion clone, an ops desk and a personal vault at once. It is one thing: living pages a team and its agent keep together.

In plain words

A small team opens one workspace. They write pages the way they would in Notion, and they ask Washi for pages the way they would ask a colleague. Some pages are tables that behave like trackers; some pull live views and charts out of those tables; some are canvases of ideas. Washi files tickets, triages, writes the weekly review on a schedule, answers "what shipped this month" from the tables rather than memory, and says every time it touched something. When a person returns, the Inbox says what moved and what needs them.

The bet

Living pages a team and its agent keep together. Not a prettier document, not a smarter chat: pages that are bound to data, kept current by routines and an agent, edited live by people and Washi at once, with nothing on them invented. Every flow in this document is designed against that sentence, and every rule in §06 exists to keep it true.

02

Who it is for

Small teams on one workspace. A workspace is a team's — one Better Auth organization, one SQLite file — and the desktop is either a client of that team's server or a workspace of one, offline.

Audience first: teams of two to twenty who already keep docs, a backlog and a weekly ritual somewhere, and want one place where the agent is a teammate rather than a sidebar. Solo use works and is not the design target; phase 7 makes it a first-class deployment of the same code.

04

Jobs and golden flows

Make it, wire it, let it live, work it together, come back to what moved. Five flows cover the product; every screen in design/ is a moment in one of them.

A · Ask for a page, type a page

  1. Mika presses ⌘J and asks: "track our Q4 hires". Washi's turn streams in the popover; sheet_check passes once because the instructions say a <Sheet> takes a title.
  2. sheet_create is a change tool: it lands without asking, the page opens, and the turn ends in Washi's words. Where it ran and what it cost is recorded, and read in Settings → Usage (D62).
  3. Rin opens the same page and types. Plain blocks become typed blocks; the Database Washi made stays a locked block, byte for byte. / drops in a new database, a linked view or a progress chart. Saves go through sheets.update with baseVersion.
  4. Washi rewrites a paragraph mid-edit. Rin's editor absorbs it only while it has nothing unsaved; otherwise the next save merges on the Loro fork and re-validates.
  5. Washi's blocks carry the indigo bar, name their source and offer Undo. Each Washi write pushed the prior page onto sheet_revisions; the stack clears the moment a person edits, so Undo never erases their words.
  6. The </> toggle opens source mode: raw WSX in CodeMirror, checked client-side exactly as the server checks it, autosaved only while valid.

done whena page asked for and a page typed are the same kind of page, and nobody's save wins over anyone else's.

B · A living page

  1. A page binds a view: <Board bind={{ table: 'issues', where: [...] }} groupBy="status" />. Bound primitives ship empty, loading and error states; the page may override only the empty sentence.
  2. The header says live, who is on the page, and when it last moved. A bound page always says one of: live · updated n ago · cached · stale · failed.
  3. Every mutation under sheets.*, tables.*, capabilities.* emits workspaceChanged on one bus; so does each finished Washi write. Clients hold one live.onChange subscription: pages refetch the list, data refetches through PaperHost.onDataChange.
  4. A routine at 17:00 in the asker's zone rewrites only the review's "This week" callout. It is an ordinary turn: daily stop and desk apply, the receipt is recorded; its questions wait 12 h.
  5. A drag on the Board is table.reorder; a cell edit is table.update. Both go through updateRecords, so record_changes remembers and a Chart history replays the day.
  6. Presence is a 15 s heartbeat in memory, never a record. Washi appears for 20 s after each rewrite of the page.

done whena page bound to a table never shows a stale row to anyone, and says when it last moved without being asked.

C · Team work — the golden flow

Mika asks why signups stalled; Rin fixes it; a week later the number confirms the fix. Nobody writes a status update. Condensed from design/work.html; the six calls below are decided.

  1. Investigation. Mika opens the template: question, evidence, hypotheses, findings. /stat drops in a live metric chart; Washi annotates the drop with the deploy that caused it, from events, not hand-drawn lines.
  2. Make ticket. ⌘⇧T on a finding. Washi pre-fills project, sprint, assignee and a Done when bound to the metric already in the evidence; the person checks it. Batch: "turn these into tickets". Escape keeps nothing.
  3. Sprint board. Four columns. The card's signal row shows only what exists: PR dot, metric against target, canvas node count, source investigation, estimate. Progress counts verifying apart from done.
  4. Ticket, peek and full. Space peeks over the board; ↵ opens the tab. Centre: problem, approach (from the canvas), Done when, relations, one activity stream. Rail: Properties always; Watching, Development, Canvas only when they exist. Development is read-only.
  5. Stat page, focused. From the ticket, the metric opens focused: value now, delta since the event that matters, target line, deploy diamonds, the shaded watch window, and Watched by — every ticket and investigation pointing at it.
  6. Ideas canvas. A ribbon names the ticket it serves. Options are nodes; a timed vote informs; Choose writes the ticket's Approach and greys the rejected options with their reasons. Washi lays out and clusters when asked, never adds options of its own.
  7. PR card and rules. The GitHub app attaches PRs by key in branch, title or body. One card through draft → open → merged → deployed. On failing checks Washi says which and what that blocks — no diff critique, no merge button. Rules move the ticket: PR opened → In review; deployed to production → Done + start watches; moves are logged by rule.
  8. The loop closes. The 7-day watch holds: the bound Done-when ticks itself, Washi drafts a Resolution and proposes Resolved, Mika flips it, Rin's Inbox says so, Friday's review reports it in one line. A miss makes a linked follow-up ticket and reopens the finding; the original stays closed.

D · Review and approval

  1. Reads pass: sheet_list · sheet_get · sheet_check · sheet_backlinks · search · db_list_tables · db_query · db_history · people_list.
  2. Page and table writes land without asking — sheet_create · sheet_replace · db_define · db_mutate — marked edited_by = 'washi', each with the prior state on the undo stack. The open page reloads under the reader; the live marker says Washi was here.
  3. fetch_url, web_search and action_run always stop at the ApprovalDesk. The prompt is inline in the panel and in words, never a tool name or JSON. "Always" on a fetch or a search lists that host (api.exa.ai for Exa) on the workspace's allowlist, never a blank cheque for the session. A panel opened late still answers: agents.pendingApprovals lists the live ones; boot expires rows a dead process left.
  4. An unanswered approval is a denial after 5 min (12 h for a routine). Stop answers its open approvals "no" and ends the turn cancelled, priced from the first stream event.
  5. The daily stop: one workspace-wide cap in metered dollars (default $25) and a turn cap (default 200). A plan turn lands in saved_usd, counts as a turn, never toward the dollars. Tripped, nothing runs until a person presses Resume, which grants one more cap of headroom, not amnesty.
  6. Who said yes is stamped from the session (approvals.resolved_by); every capability call, allowed or refused, is a ledger row with its actor.
  7. The Inbox is the return: mentions, what moved, what needs you. Today (the dashboard) retells the last day from the transcript and the desk — nothing new stored, nothing invented.

done whennothing leaves the workspace without a person, every change inside it is marked and undoable, and the Inbox is the only place anyone has to look.

06

Rules that cannot bend

Law, not guidance. A design or a PR that breaks one of these does not ship, however good the reason sounds. Each carries its one-line why.

Constraints — what keeps phase 7 a redeployment

C1
A workspace is one SQLite file, hosted too. Postgres holds identity only.Accounts, organizations, members, invitations, encrypted keys — nothing else. Content in Postgres rows keyed by org means a second repository, which is the same as never shipping local mode.
C2
One binary, mode: hosted | embedded asserted once at boot. Never per request.Hosted refuses to boot without its secrets; embedded binds nothing and answers "one actor, one workspace, no auth". Auth decisions scattered as implicit truths are where an auth bypass ships.
C3
repository and service never see a request, a user or the network.They take a resolved Workspace and an actor. No session, no Better Auth, no Postgres import below trpc. contextFromRequest is the one place a header or a socket is read.
C4
The desktop is the web client in a mirin window.Same appRouter over IPC, no native-only data paths, no desktop-only procedures. Special cases here make local mode a third implementation.

WSX — what a page may be

W1
WSX is inert data: registry primitives, literal props, the closed expr grammar. Validated before persist and before render.A hallucinated or prompt-injected page is wrong content, never code. On a shared workspace this is the reason it is safe at all. state, expr, bind, action are a page's whole behaviour.
W2
The registry is closed and additive. Components own appearance — four enums (variant tone size emphasis) — pages own content and meaning.No hex, no font size, no margin in a page. A capability the registry lacks is <Missing kind reason />, never an escape hatch. See wsx-primitives.html.
W3
Pages size to their container, never the window.The same tree renders at 320, 400, 720 and full width; @sm: @md: @lg: only. The sheet is a bare surface (Q18): page chrome is drawn above it, outside the paper.

Agent — what Washi may do

A1
Agent tools are the only capability surface: ink (data) · tsuru (network) · hanko (actions). Never fs, shell or raw SQL.Every identifier in an ink descriptor is membership-checked and bound as a parameter. Default SDK tools are off (tools: []). Power grows by adding tools and primitives, never a scripting hatch.
A2
Reads pass. Page and table writes land, marked edited_by = 'washi', with an undo stack. fetch_url, web_search and action_run stop at the desk.Nothing leaves the workspace without a person — or without a workspace's standing yes: an owner may set approvals to auto (D56), and then every outbound call is written to the ledger as auto instead of asked. Refusals (http, private ranges) refuse in both modes. A click in a page is consent for reversible in-workspace verbs only; url.open from a page is refused until its consent UI exists. The ledger records both origins, allowed and refused.
A3
A team server never bills one person's plan.Hosted runs on the workspace's stored key and has no local branch. Embedded runs the person's own claude with no key in the env. The subprocess env is built from an allowlist, never inherited — WASHI_SECRET_KEY must not reach the agent.
A4
Washi never reviews code.PRs are read-only context: linked to tickets by key, checks and deploys shown, status moved by rule. No diff critique, no review comments, no merge button. Asks come from docs, tables and sprint ops.

Persistence — what the file promises

P1
Every record write goes through insertRecord · updateRecords · deleteRecords.Each appends what the row became to record_changes. Charts, burn-ups and "done this month" replay it; a write around it makes history silently forget.
P2
Writes merge. The Loro doc is the source of truth; source is a cache; baseVersion replays a write on a fork and merges it into the present.A merge that breaks WSX is SheetConflictError, never a silent save. Without baseVersion a write still replaces — the editor and sheet_replace always send it.
P3
Nothing on screen is invented. Empty states are the honest default.A product whose promise is "see what the agent did" cannot show placeholder history. Today reads the transcript; the Daily note waits for real data; a control that does nothing is removed, not styled.

Brand and stance

B1
One house style. Keep the brand: the chibi sheet, warm persimmon on cream paper, washi-chan.The app frames; pages carry the house style through feel and theme. Mascot moods map to real agent states only. Source and rules in brand.html and mascot.html.
S1
Always self-hosted. The badge shows the host only; the product never pitches self-hosting.OSS, no pricing, no plans, no seats — now or later. Each team holds its own keys in its own Postgres; the bar is "a database dump must not leak it", not an escrow.
07

Architecture

One runtime, two hosts. @washi/runtime boots in embedded (the desktop's main process) or hosted (the studio); both serve the same appRouter — the studio over HTTP + /trpc-ws, the desktop over mirin IPC.

Packages and layering

  • Client code imports @washi/trpc/client, never the barrel. The barrel carries the router, the service layer and the Agent SDK into the browser bundle.
  • Import @washi/control/embedded for the stub. The root barrel pulls Better Auth and a Postgres driver into the desktop main process.
  • One React repo-wide (root overrides): Bun's isolated linker would otherwise hand workspace packages a second copy — an invalid hook call.

Data — two planes

The sheet — source of truth

  • A Loro text doc, snapshot blob in SQLite; source is a cache. sheets.get hands out version (encoded frontiers).
  • A write that sends it back as baseVersion is replayed on a fork at that version and merged into the present (mergeSheetSource), then re-validated. A merge that breaks WSX is SheetConflictError; a stale editor merges on its next save rather than overwriting.
  • An open editor takes a remote change in only while it has nothing unsaved (absorb, ids kept per row). A canvas hand edit goes through PaperHost.replaceNode(from, to); in the editor it routes into the editor store, so autosave never writes a stale canvas over a fresh one. One writer per loaded page.
  • The look — icon and cover (a key: preset:…, picture:… or file:… — never a URL, D60) — is the page's own: <Sheet icon cover> props, drawn by paper, cached in sheets.icon/cover by every write (D64). sheets.updateMeta writes a picked icon or cover into the doc (merged, an edit); full_width and rename stay metadata, and width alone is not an edit.
  • Nesting: parent_id + fractional position; a move rewrites one row; a move into its own subtree is SheetMoveError → 400. Delete trashes the subtree under one deleted_at; a restored page whose parent is gone comes back at the top.
  • serialize writes text with <{}>&, runs of spaces or newlines as a string literal, so typed text round-trips. Invalid WSX is a 400, never a 500.

Live

  • One bus. Every mutation under sheets.*, tables.*, capabilities.* emits workspaceChanged { workspaceId, kind: page | data, id }; agent-watch emits it for each finished Washi write.
  • Clients hold one live.onChange; pages refetch the list, data refetches through PaperHost.onDataChange. Subscriptions yield tracked() and resume from lastEventId; the bus survives a slow consumer (the 256-event deafness and the lost wake-up both have tests).
  • Presence: live.here every 15 s, in the runtime's memory, never a record. Washi is on the page for AGENT_PRESENCE_TTL_MS (20 s) after each rewrite.
  • Comments and mentions still poll (30 s). Keystroke-level sync is phase 8's raw-binary /sync; Loro deltas have no business in JSON.

The agent host

  • Two ports, one vocabulary. AgentPort — prompt · cancel · resume — normalizes into one AgentUpdate shape. ClaudeSdkPort (Claude Agent SDK, in-process MCP tools) and AiSdkPort (AI SDK 7 ToolLoopAgent, OpenRouter first; toolApproval on the agent, not the deprecated needsApproval). Both stay. The catalogue is models.dev (317 tool-capable models, daily refresh, bundled floor); an unpriced model yields null cost, not zero.
  • Credential kinds: api_key | local_cli. Embedded auto finds claude and runs it via pathToClaudeCodeExecutable with no key in the env; hosted is api_key only, asserted at construction. init.apiKeySource is none for a claude.ai login — the binary, not the docs, set that rule.
  • Plan vs metered. A plan turn lands in saved_usd (a $25 notional ceiling, never absent); a keyed turn in cost_usd with a $5 turn ceiling. The daily stop counts metered dollars (default $25) and every turn counts toward the turn cap (default 200). Resume grants one more cap of headroom.
  • Sessions. One in flight per session; agents.cancel aborts and answers its approvals "no"; a resume the CLI no longer knows retries once, fresh; a session left running by a killed process is error at boot.
  • Routines run on the minute clock over the workspaces the control plane knows that already have a file — never a stray, a deleted one or a conjured default. One in flight per workspace, parked or not; marked run before it runs; a scheduled run's questions wait 12 h; at the daily stop nothing is marked and the day catches up after Resume; times are wall-clock minute + IANA zone. routines is the only caller-free path into a turn — keep it that way.
  • Every turn records a receipt — where it ran, model, duration, cost or saved — and no conversation shows it (D62): cost is read in Settings → Usage. Instructions name the tools in words; the UI never shows a tool name or JSON.

D73A column can be a formula decided [2026-10-27 · Washi's expense-tracker report]Washi: month is typed in by hand, so a row dated 2026-11-01 can end up under the wrong month … Overdue and days-until-due are also impossible, and COP isn't recalculated when the rate changes. A table column of type formula carries an expr in the page grammar over its own row — month(date), usd * fx_rate, when(paid, false, days(now(), due) < 0) — with three new functions (month, year, when; if stays reserved). It is computed on every read and never stored: a write to it is refused, a bad expression is refused when the table is defined, and a formula that fails on a row is null for that row. It reads the row's scalar columns and earlier formulas, never other rows (that is a rollup). Filters, order and grouping on a formula work like any column, finishing in memory over at most 5000 rows. A shared link hides every formula that reads a redacted column, however indirectly (D65).
D74A column can roll up another table decided [2026-10-27 · Washi's expense-tracker report]Washi: No budget vs actual per category … That is the most useful view for a budget, and I can't build it properly, and Budgets can't roll up from expenses. A rollup column holds one aggregate (count sum avg min max) over another table's rows that point at this row — through a relation holding its id (so a rename keeps every row), or a plain value equal to this row's on column (so a choice column works before anyone converts it) — after an optional where. A where value may be { param }: a query's params fill it, a page's params may read state, and an unset one drops its filter (all time). Computed on read, one read of the target per rollup column, before formulas — so left = budget - spent is a formula — never written, never over another rollup. A shared link hides a rollup over a table the page doesn't read or a column it redacts there, and every formula built on one. A choice column becomes a relation in one step (db_link_column): each value names the target row whose text column reads the same, missing ones are created only when asked, and from then on a rename reaches every row.
