washi。

A team workspace of living pages. People and the agent write them together; the agent keeps them true.

teams first co-authored · live living pages desktop works offline, solo called 2026-10-14 supersedes features.md §1 · §2 · §5

30-second version

  • Teams first. A workspace is a team's. The studio is home; the desktop is a client of a team server — or, offline, a workspace of one.
  • Both write, as equals. Type into a page or ask for one. The editor is a first-class surface, not a touch-up tool.
  • Live together. Co-editing comes forward: teammates and Washi edit the same page at once, and Washi's edits land directly, marked as its own.
  • The job is living pages. A page is bound to tables, fetched data and routines, and says when it is live and when it last moved.
  • Canvas joins the primitives. A node-and-edge board (React Flow) is a WSX primitive like Table or Stat — inert data, editable by hand and by agent.
  • The team's work lives here. Backlog, roadmap, wiki, ideas and a review that pulls live views from all of them, with graphs over time. No second tool.

03 · the loop

Base usage

Make it, wire it, let it live, work it together, come back to what moved. Every flow we design is one of these five steps.

  1. 1

    Make

    Type a page, or ask: "track our Q4 hires". Same page either way.

  2. 2

    Wire

    Bind it to a table, a fetched source, or a routine. It now carries a live marker.

  3. 3

    Live

    Routines refresh it; Washi updates it. "Live · updated 2m ago", cached, or stale — always said.

  4. 4

    Together

    Teammates and Washi edit at once. Comment, @mention, ask Washi about one block.

  5. 5

    Return

    The Inbox shows what moved while you were away, and what needs you.

05 · together

Co-editing comes forward

"Multiplayer is review, not co-editing" is retired. Two people and an agent type into one page, live, and nobody's save wins over anyone else's.

CallWhat it means
Live co-editingdecided Loro stops being a storage format: the server holds the live doc, clients sync deltas over /sync (raw binary WS). Presence shows who is on the page.
Washi edits land directlydecided Washi is a collaborator in the doc — its edits merge live, marked as its own, and undo as one change. No desk stop for a page you are both in.
Live markerdecided A bound page says it: live, updated n ago, cached, stale, failed.
The deskopen · Q1 Still guards what leaves the workspace (fetch_url, action_run). Whether any page write still stops there is Q1.
What this costs in code
  • The block editor edits the Loro doc, not a WSX string through sheets.update.
  • Spec Q2 (whole-doc source) falls: blocks need stable ids to merge.
  • Validation moves to merge time — a merged doc must still be valid WSX before render (P8).
  • Peer sync (old phase 8) splits: server↔client sync now, desktop↔server sync with local mode.

10 · open

Still to call

Each one changes a flow we are about to design.

Q1

Does any page write still stop at the desk?

Washi now edits live. Routines and asks from the popover write pages too.

No. Page and table writes land, marked and undoable. The desk keeps what leaves the workspace.

Q2

What can a canvas node hold?

A label, a link to a page, or other primitives (a stat, a table row)?

Label, tone, link to a page. Nested primitives later.

Q3

Is Washi visible in the page while it writes?

A presence cursor like a teammate's, or only a mark after the fact?

Presence while writing, authorship mark after.

Q4

Can a solo desktop workspace join a team later?

It is one SQLite file (C1), so it can be uploaded.

Yes, as a one-way move, with local mode.

Q5

Generic tables, or a built-in Issues model?

Linear ships one opinionated issue shape. Notion ships blank databases and templates.

Generic tables plus the team-space starter, with three new column kinds: status (grouped todo · doing · done), person, relation. One engine, and Washi already speaks ink.

Q6

Is a row a page?

A ticket needs a description, comments and activity, not just cells.

Yes. Any row can carry a body page — peeked in a drawer, opened full. Comments and @mentions come with it.

Q7

How do charts learn the past?

A burn-up or "done this month" needs each row's history.

An append-only change log per table, in the workspace file (C1). Ink gains a closed history query. Not nightly snapshots — they leave gaps and cost turns.

11 · next

Design before code

Flows first, in loop order. No implementation until a flow is drawn and called.

  1. Make a living page — type or ask, then wire it to data.
  2. Run the week — ticket in the backlog → board → roadmap → review doc → month graph.
  3. Work it together — teammate + Washi in one page, presence, comments.
  4. Return — the Inbox as "what moved" and "assigned to you".
  5. First run — join a team (the team-space starter), or start solo on the desktop.
  6. Canvas — draw, connect, ask Washi to map something.

The brand sheet runs alongside flow 1.
