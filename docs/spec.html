30-second version

  • Sheets are WSX — JSX as a serialization format. Closed component registry, JSON-literal props, zero executable code. Agents can't malform it; validation errors are actionable.
  • Two agent ports, one UI. Embedded Claude Agent SDK is the native path; external agents (Gemini, Codex) arrive later over ACP. The transcript UI speaks ACP vocabulary for both.
  • Ink, the data DSL. One typed query/mutation grammar (@washi/ink) shared by Paper bind props, agent tools, and the UI — agents define tables, add rows, and query through it. The outside world only via capabilities: policy-gated fetch + stamped actions. Never fs or shell.

01 · core concepts

Eight nouns, one bet

Humans direct, agents write. Everything an agent touches is typed, scoped, and closed.

  • Sheet — one note. A .wsx document stored in SQLite (not loose files).
  • Paper — the closed UI kit (@washi/paper). The only components a sheet may use.
  • Tables — user/agent-defined structured data, Notion-database style. Sheets embed live views via bind props.
  • Ink — the typed data DSL (@washi/ink): define tables, insert, update, query (filters, sorts, group-by aggregations). One grammar shared by bind props, agent tools, and the UI.
  • Tsuru — scoped fetch (@washi/tsuru): https-only, domain allowlist + per-domain prompts, private ranges blocked. Shared by agent fetch_url and the sheet Fetch component.
  • Hanko — safe actions (@washi/hanko): a closed registry of stamped verbs (open sheet, insert row, open URL…) — the only side-effect channel for sheets and agents.
  • Agents as first-class editors — embedded Claude native, ACP agents pluggable.
  • Closed APIs — sheet CRUD, table query/mutate, search. Zod at every boundary, permission-gated.
02 · wsx format

JSX as data, not code

A sheet is a validated AST wearing JSX syntax. Nothing executes — a hallucinating agent writes wrong content, never running code.

<Sheet title="Q3 Roadmap" icon="🗺️" tags={['planning']}>
  <H1>Q3 Roadmap</H1>
  <Callout tone="warning" class="mt-6 font-medium">Dates aspirational.</Callout>
  <TaskList bind={{ table: 'tasks', where: { tag: 'q3' } }} />
  <Table bind={{ table: 'tasks' }} columns={['title','status','owner']} />
  <Button action={{ verb: 'table.insert', table: 'tasks' }}>Add task</Button>
  <Ref sheet="01J8…">design doc</Ref>
</Sheet>

Grammar DECIDED

  • Elements: Paper registry components only. No host elements, no imports, no user components (v1).
  • Props: JSON literals + bind ink descriptors + sheet refs. No functions, no expressions.
  • Style: Tailwind is the styling language — every component takes a class prop with the full utility vocabulary (arbitrary values, gradients, variants), compiled at runtime by @tailwindcss/browser. Guard: no url(), no quotes/braces — styling is expression, never a network capability. Generic Box/Span primitives make free-form layout possible. REVISED 2026-08-13
  • Actions: interactive components carry action props — hanko descriptors from the closed verb registry. No callbacks, no scripts.
  • Children: elements, text, {literal}.
  • Validation: Zod props schema per component (lives in @washi/paper/registry, main-process safe), runs before persist and before render. sheet_check returns diagnostics agents can act on. render side missing — P8 Today SheetView parses but does not re-validate, so a sheet persisted under an older registry renders unchecked props.
Why JSX over markdown
  • Typed structure agents can't malform — parse + schema errors instead of silently broken markdown.
  • Richer-than-markdown blocks: kanban, live tables, charts, columns — one grammar for content and layout.
  • Interactivity lives inside Paper components (task toggle, cell edit) writing back through fixed RPC mutations.
Paper v0 — ~15 components

Sheet · H1–H3 · P · Quote · Callout · Code · Divider · Img · Ref · Tag · TaskList/Task · Table · Board · Toggle · Columns/Column · Button · Fetch (tsuru-policied, async render, cached last-good) · Hero · Tape · Stamp · Chip · Stat · Card · Timeline/Step · Box/Span · Tabs/Tab · Accordion/AccordionItem · Dialog · Tooltip · Badge · Avatar · Progress · Skeleton · Switch · Slider · Kbd · Show

Sheet state (the "hooks" answer): state={{ key: scalar }} on <Sheet> declares a validated store; Switch/Slider/Tabs write keys, <Show when equals> reads them. Interactivity as data — no handlers, no hooks. Sandboxed expressions are open question Q11.

Sheet themes: theme={{ accent, face, paper }} — closed presets (tape-color accent · gothic/serif/rounded face · plain/dots/lines paper), so one registry carries many design directions. Showcase sheets seed with the app.

Impls wrap shadcn/ui primitives (base-mira) — app chrome and sheet content share one design system and one token set.

04 · data layer

One SQLite file, sync-shaped

ULIDs + HLC timestamps + tombstones + oplog from day 1. Cheap now, cursed to retrofit.

  • <appDataDir>/washi.db, dev fork via app.isDev. WAL, FKs on. One file, one vault — the UI's vault switcher has no data layer under it yet Q12.
  • All writes route through repository ops that also append to oplog — the future sync unit. not atomic — P2 Row, oplog, FTS and links are four separate statements with no transaction; the oplog stores whole writes rather than patches, is untyped, and nothing reads it.
  • Table reads/writes travel as @washi/ink descriptors — the same objects whether they come from a bind prop, an agent tool, or the UI. Ink is the SQL boundary: every identifier in a descriptor is membership-checked against the table spec and bound as a parameter, never string-interpolated. enforced — P0 closed
  • Sheet writes are whole-source replaces DECIDED — Loro merges them at the text level when devices diverge.
  • Sheet source is a Loro text doc from day 1 DECIDED — snapshots + update log persisted in SQLite; tables and metadata stay LWW via HLC + oplog. half-built — P3 Snapshots exist; the update log, a stable per-device peer id, and delta export do not.

05 · agent layer

Two ports, one vocabulary

The transcript UI renders ACP semantics — message chunks, tool cards, diffs, plans, permission options — no matter which agent is behind it. claude-agent-acp proves the SDK→ACP mapping is 1:1.

Embedded Claude — native path M2

  • @anthropic-ai/claude-agent-sdk in the main worker.
  • Tools via createSdkMcpServer (in-process, zero IPC): sheet_list/get/create/replace/patch, sheet_check, db_define/insert/update/query (thin wrappers over @washi/ink descriptors), fetch_url (tsuru), action_run (hanko), search, link_graph.
  • Default tools (Bash, fs, web) disallowed; opt-in per session via permission UI.
  • canUseTool → approvals store → renderer prompts (Anko's approval-manager pattern, generalized).
  • Hooks for audit · maxBudgetUsd per session · sessions persisted/resumable. per turn, not per session The cap is passed to each query() call; the stored cost_usd is never enforced against.
  • Turn control — one in-flight turn per session, cancellable. missing — P6 promptAgent is fire-and-forget, so errors vanish and nothing can interrupt a running turn.

ACP client — external agents M4

  • Spawn agent binaries (gemini --experimental-acp, codex-acp, claude-agent-acp) via Bun.spawn; @agentclientprotocol/sdk over stdio.
  • Washi's tools reach them via MCP passthrough at session/new — reuse Anko's token-auth loopback HTTP MCP server.
Trust model
  • Agent-written WSX is inert data — registry-only, no expressions. Worst case: wrong content, never code execution.
  • DB access only through Zod-validated tools; no raw SQL surface.
  • Network only through tsuru: https-only, domain allowlist + per-domain prompts, size/time caps, loopback and private ranges always blocked — agents can never reach the mirin RPC or MCP loopback servers.
  • Side effects only through hanko verbs — each stamped by the approvals flow, each an auditable row. both origins gated — P4 closed One gate, origin stamped by the route; every call lands in capability_calls.
  • Loopback servers token-gated, off in packaged builds unless explicitly enabled.
  • Streaming: agent host normalizes both ports into one update shape → rpc.event broadcast → Zustand agent store → transcript UI.

07 · sync (future)

Self-hosted relay, not a merge brain

Server pushes/pulls oplog and holds auth. It never merges — which keeps E2E encryption on the table.

  • apps/sync — Bun + Elysia + Eden, Better Auth (JWT/jose), Postgres. Docker for self-host, Railway template for one-click.
  • Conflicts: sheet source merges via Loro (storage in place since M1, merge not yet earned — P3); metadata/records = per-entity LWW via HLC.
  • Entry condition: the oplog replays into an empty database and reproduces the vault. Until that test is green, "sync-ready" is a claim, not a property.
  • E2EE of op payloads follows sync rather than blocking it Q19 — ops carry an opaque envelope from day 1, so encryption is later key management, not a migration.

09 · hardening (M2·5)

Where the document and the code disagree

An audit on 2026-08-14 read every layer against this spec. The architecture holds — the closed grammar, the one-way layering, the three capability packages are all real. What doesn't hold: four load-bearing claims. One is a hole straight through the trust model.

P0 · the ink executor is a raw SQL surface FIXED 2026-08-14

P0 Column identifiers reach SQLite unchecked closed

claim
"DB access only through Zod-validated tools; no raw SQL surface." (§05)
reality
runQuery membership-checks where, orderBy and groupBy.column against the table spec — but not groupBy.aggregates[].column. The executor interpolates it into json_extract(data, '$.…') and into the AS "…" alias. Zod only asks for a non-empty string, so the quote is right there.
reach
Both capability paths: an agent calling db_query, and any rendered sheet whose <Table bind> / <Board bind> carries the descriptor — so a hallucinated or prompt-injected sheet fires it on render.
fixed
Two layers. The service membership-checks every descriptor slot that names a column, aggregates included; the executor binds JSON paths as parameters behind a shape assert, so a caller that forgets the first gate still cannot interpolate. GROUP BY 1 and alias-ordering keep each path bound once. Tests cover the slots rather than the payload.
bonus
The executor's assert immediately caught a second instance the audit had missed: runMutation never membership-checked its where columns at all. Defense in depth earned its keep on day one.
// the probe that proved it — nested subquery over sqlite_master, executed
runQuery({ table: 'tasks', groupBy: { column: 'status',
  aggregates: [{ fn: 'sum', column: "title') + (SELECT 40 + (SELECT count(*) FROM sqlite_master
                             WHERE name='approvals') + 1) + json_extract(data, '$.title" }] } })

→ { rows: [{ status: 'open', "sum_title') + …": 42 }], total: 1 }

P1–P4 · the load-bearing four

P1 "Live bindings into a local database" are not live

reality
Binds fetch once per mount and never again — the effect keys on the query, not on the data. There is no data-change event anywhere: the RPC surface broadcasts three events, all agent-transcript. When the agent rewrites the sheet you are reading, SheetView keeps rendering the old tree until you switch tabs; when it inserts a row, every open <Table> lies. The only refresh in the app is turn_done → re-list the sidebar.
fix
One dataChanged event carrying { entity, ids }, emitted by repository writes through a service-level emitter (never from the renderer). Renderer subscribes once: sheet ids re-fetch the active tab, table ids invalidate the binds that touch them. Ink descriptors are already canonical JSON — they are the query keys. This is a small reactive cache, not React Query.
why now
M3 puts tables in front of the user. Stale-by-default data is a bug the demo cannot survive, and every M3 surface inherits it.

P2 Writes aren't atomic; the oplog isn't a sync unit

reality
Zero transactions in the repository. A sheet write is four statements — row, FTS reindex, link rebuild, oplog append — and a crash between them leaves the vault internally inconsistent. The oplog itself stores whole writes (a full copy of every sheet source, forever), is typed as opaque JSON, has no reader, no cursor, and no consumer.
fix
withTransaction() in the repository client; every op function becomes one unit including its oplog append. A typed Op discriminated union in domain (entity · id · patch · HLC · device), ops as patches rather than snapshots, plus readOps(sinceSeq) and compaction.
proof
A test that replays the oplog into an empty database and asserts vault equality. That one test is what makes M5 credible; without it, "sync-shaped" is decoration.

P3 Loro is a snapshot store wearing a CRDT costume

reality
Every save constructs a fresh LoroDoc, imports the blob, calls update(next), exports a full snapshot. So: a new random peer id per write (the history accumulates a new actor every save), no update log despite §04 promising one, no version vector, no delta export. Q4 chose Loro on day 1 precisely to solve multi-device merge before sync exists — that value is currently unbanked.
fix
Stable peer id derived from device_id; persist incremental export({ mode: 'update' }) deltas in a sheet_updates table; snapshot-compact on a threshold; expose exportFrom(versionVector) so M5 ships deltas instead of documents.
proof
Two docs, divergent edits, merge → both converge and neither loses a paragraph. Currently untestable, which is the tell.

P4 Sheets walk past the approvals desk closed

claim
"Side effects only through hanko verbs — each stamped by the approvals flow, each an auditable row."
reality
True on the agent path (canUseTool → approvals table → renderer prompt). False on the sheet path: the runAction route called the executor directly. Identical verb, identical blast radius, no gate and no row — and the sheet that carries it was written by an agent, so this was the agent path with the desk removed.
fixed
executeAction takes an origin the route stamps, never the caller. Per Q13 a click is consent for reversible in-vault verbs and never for anything leaving the machine; url.open from a sheet is refused. The capability_calls ledger records both origins including refusals — the additive move below, shipped early because P4 needed it.
owed
A sheet's url.open is refused outright rather than prompting with the full destination. The confirm UI is the remaining half of Q13; no sheet uses the verb today.

P5–P8 · the rest of the queue

P5 Approval policy lives in a Map

reality
alwaysAllowed is per-process, keyed by session, gone on restart — while allowed fetch hosts persist to app_meta. Two mechanisms, two lifetimes, one concept.
fix
One persisted policies table: subject (tool / verb / host) × scope (session / vault) × decision. It is also, for free, the "agent autonomy" surface the design already mocks in Settings.

P6 "Two ports, one vocabulary" is a claim, not a structure

reality
AgentHost is welded to the Claude SDK and also owns approvals, hanko dispatch, sheet fetch and diff emission. No port interface exists, so M4 is a rewrite rather than an implementation. promptAgent is fire-and-forget: no cancel, no concurrency guard, errors swallowed by void.
fix
Extract AgentPort — prompt · cancel · resume · setModel, normalizing into the existing AgentUpdate shape. ClaudeSdkPort is the first implementation, ACP the second. Add an AbortController per turn and a per-session queue. Move hanko dispatch out of the host into its own service module.

P7 Vaults exist in the UI and nowhere else

reality
A vault switcher and a create-workspace dialog ship in the app. Underneath: one module-singleton database at one fixed path, opened once at boot. Every day this stays true, the retrofit gets worse — the same argument that put HLC and tombstones in on day 1.
fix
Decide Q12 now, build it at M3. Recommendation: one SQLite file per vault, database handle becomes a resolved dependency instead of a module singleton, vault = the natural sync and export unit.

P8 Render trusts what persist validated

reality
SheetView parses and renders; it never calls validate. Persisted source was checked against the registry of the day it was written — narrow a prop schema or retire a component and old sheets render unchecked, class-token ban included.
fix
Validate in the render path and render diagnostics as a repairable state ("this sheet predates the registry — ask the agent to fix it"), which is also the honest UX for a closed, additive registry.

Three additive moves architecture, not repair

  • State-parameterized binds — let a bind's filter value reference sheet state: where: [{ column: 'status', op: 'eq', value: { $state: 'filter' } }]. One new node in the ink schema, resolved in the renderer before the descriptor crosses RPC. Still inert data, still no expressions — and a tab strip that filters a live table covers most of what Q11 was ever asked for. See Q14.
  • A capability ledger shipped 2026-08-14 — capability_calls, append-only, one row per sheet action and fetch with origin, subject, input, decision and detail. Shipped early because P4 needed it. Still owed: agent tool invocations, which ride with P5.
  • Ink descriptors as query keys — canonical JSON already; make it explicit and the reactive layer (P1), the bind cache, and future sync invalidation all key off one thing. Small, and it stops three ad-hoc caches from being invented later.

10 · canvas & reach

Every sheet looks like this document

Q9 gave sheets the full Tailwind vocabulary. It never gave them the last word. Three layers of imposed appearance sit between an agent's class and the pixels — so sheets converge on one look no matter what gets written. A sheet should be a blank canvas assembled from our primitives; today it is a pre-decorated page you may lightly annotate.

Why it happens — three layers, each sufficient on its own

L1 The app chrome declares what a sheet is

does
SheetView wraps every sheet in a bordered, shadowed, max-w-2xl card with a washi tape strip and a byline.
costs
No sheet can be full-bleed, edge-to-edge, wider, or its own background. The frame is the app's opinion, applied before the sheet gets a vote.
call
A bare scrolling surface — no tape, no card, no shadow, no width Q18. Washi's identity lives in the app chrome; the page is the user's.

L2 <Sheet> paints before you do

does
mx-auto w-full max-w-2xl rounded-xl px-8 py-6 plus a face class — and the washi preset applies even with no theme prop, as an inline style.
costs
Inline style beats every class. That is why the code carries a regex that sniffs class for bg-/from- and retracts the preset background — an escape hatch bolted on precisely because the architecture fights itself here. The second max-w-2xl (L1 already applied one) makes width unwinnable.
call
A bare container carrying only class. Presets become an opt-in class, never a default inline style. Want a centered column? Write class="mx-auto max-w-2xl px-8 py-6" — explicitly, like any React app.

L3 class is a suggestion, not an override

does
Every component merges by naive concatenation — cx(base, extra) is a template string. <H1 class="mt-0"> emits class="mt-6 mb-2 … mt-0".
costs
Two conflicting utilities both land on the element, so the winner is decided by Tailwind's canonical stylesheet order rather than by the author — and for same-family utilities the baked-in default typically outranks the override. tailwind-merge is already a dependency of the app; @washi/paper does not use it. This is the mechanical reason the vocabulary feels decorative.
call
twMerge in every component so exactly one utility per property survives, and the sheet's is the one that does.

The deeper problem: the registry is a washi kit, not a primitive set

  • Hero hardcodes the 。 — this document's signature, welded into a general-purpose component.
  • Tape and Stamp are brand furniture living in the default vocabulary.
  • Divider accepts no class at all. Board pins columns at w-64, Dialog at max-w-md.
  • Every block carries cosmetic margins, radii and borders that a sheet must fight rather than compose.

Split the registry in two: primitives carry behavior and semantics only — bind, state, action, structure — and ship zero cosmetic classes. Styled kits are opt-in, one word on <Sheet>. The washi look stops being the floor and becomes one choice among many.

// today — the sheet asks politely and the registry declines
<Sheet title="Launch" class="bg-black max-w-none">
  <H1 class="mt-0 text-white">Launch</H1>   ← mt-6 still wins

// after — nothing is painted until the sheet paints it
<Sheet title="Launch" class="min-h-full bg-black text-zinc-100">
  <Box class="mx-auto max-w-3xl px-6 py-16 @md:px-12">
    <H1 class="text-6xl font-black tracking-tighter">Launch</H1>
  </Box>
</Sheet>
The tradeoff, stated once

A blank canvas means an unstyled sheet looks like unstyled HTML. The agent has to actually design, every time. Three mitigations, none of which reopen the grammar: the sheet_create scaffold ships a fully-composed layout rather than a bare <H1>; presets survive as one-word opt-ins for when the agent wants a starting palette; the system prompt carries a worked example instead of a component list. Beautiful-by-default is what produced the sameness — this is the trade being made deliberately.

Mobile — what it costs, and what it doesn't

The layering already splits in the right place. Everything above the RPC boundary is portable; everything below is Bun. Mobile is not an architecture problem — it is a runtime problem plus a layout discipline we have not adopted.

The limitations worth holding in your head

  • mirin is desktop. Bun main process + CEF renderer, no mobile target. Any phone path is a new shell — webview wrapper, Expo, or PWA.
  • The agent cannot run on-device. This is the load-bearing one: mobile is always relay-backed or paired to a desktop. It makes M5 a prerequisite for mobile rather than a sibling of it.
  • Runtime Tailwind compilation is a desktop luxury. @tailwindcss/browser ships a compiler to the client and scans the DOM. On a phone that is startup cost and memory per view. Fix once, benefits both: precompile CSS in the main process per sheet — it already holds the source — and cache by source hash.
  • There is not one responsive class in @washi/paper. Zero sm:, zero @container. Every fixed width — the max-w-2xl sheet, w-64 board columns, the max-w-md dialog — breaks at 375px.
  • Breakpoints are the wrong tool here. One sheet renders in a desktop tab, in a 400px agent popover, and on a phone — three widths, same document, and two of them are not the viewport. Container queries are the correct primitive.
  • Blank canvas makes responsiveness the agent's job. Either the prompt mandates container-query classes, or primitives stay fluid by default so the naive sheet works everywhere. Probably both.
  • Touch. Hover variants, Tooltip, Dialog triggers and <details> toggles assume a pointer; size-4 checkboxes are well under a 44px tap target.
  • The security boundary changes shape. Capabilities stay server-side — that part is already right — but loopback + token becomes network + real auth. Better Auth is already on the M5 plan; mobile just makes it non-optional.

Three shapes, in increasing cost

  • Companion — read, search, and approve. No editing, no local agent. Small, and the honest v1: on a phone this product is mostly "see what the agent wrote and stamp its proposals." The inbox is the mobile killer feature, not the editor. the shape mobile takes when it returns
  • Thin client — full app over the relay, @washi/paper reused verbatim in a webview. Medium, gated entirely on M5. Online-only unless a read cache gets built.
  • Local-first mobile — port repository behind an interface (op-sqlite or expo-sqlite, Loro via WASM), agent still remote. Large: every repository function reaches for getSqlite() directly and raw SQL is spread across it.

Mobile is parked Q18 · Q17 — nothing here is real before M5, because the agent can never run on-device. What is not parked: fluid widths and container queries ride along with the canvas sweep regardless. Both refactors are the same move — "stop baking desktop-page assumptions into the primitives" — one pass over ~35 components. Free now; the same pass twice, with a vault of sheets to migrate in between, if the concessions get skipped.

Q12

The UI ships a vault switcher over a single-file, single-vault database. One SQLite file per vault, or one file with a workspace_id on every table?

file per vault — isolation is free, the vault becomes the natural sync/export/backup unit, and a leaked query can't cross vaults.

one SQLite file per vault. Lands with P2 — the db client is being rewritten for transactions anyway, so the singleton → resolved-handle change rides along.

Q13

Is a click consent?

A user pressing <Button action> in an agent-written sheet — does that stamp the verb, or does it still stop at the approvals desk?

split by reversibility. A click is consent for in-vault, undoable verbs (sheet.open, sheet.create, table.insert); anything leaving the machine (url.open) prompts every time and shows the full destination. Both write ledger rows regardless — the ledger is not the gate, it is the record.

Q14

Should a bind's filter value be able to read sheet state — { $state: 'key' } — so a tab or switch filters a live table without any expression language?

yes, ships with M3. One node in the ink schema, resolved renderer-side before the descriptor crosses RPC; the sheet stays inert data. $state values pass the same column/type check as literals — skip that and Q14 quietly re-opens P0.

Q15

How blank is the canvas?

Primitives ship zero cosmetics and an unstyled sheet looks like unstyled HTML — or they keep a thin readable baseline (type scale, rhythm) that class can always beat.

zero cosmetics. Primitives carry structure and behaviour only; a "sensible baseline" is exactly how the current sameness happened — every default is a thing the agent must fight without knowing it. The sheet_create scaffold becomes a product surface, not a stub.

Sheets render at three widths that are not the viewport — desktop tab, 400px agent popover, phone. Which vocabulary do agents author in?

container queries only. sm:/md:/lg: join url() in zClass's ban list, so it is enforced mechanically rather than hoped for in a prompt. A sheet is a component, not a page — it never knows the window.
