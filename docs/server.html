server。

Washi becomes a server with clients. One Bun binary, two deployment modes. Team collaboration ships first; the local-only mode it was designed around is deferred, not cut — and four constraints are what keep that promise honest.

tRPC v11 · wsLink Better Auth organizations SQLite per workspace BYOK · org-level OSS · self-hosted · no pricing v0.6 · amends spec v0.5

30-second version

  • The client's origin is a server, and the desktop app is a client of it. mirin shrinks to window, menu, icon and sidecar spawn. The renderer and the web app consume the same tRPC router.
  • Two planes. Postgres holds the control plane only — accounts, organizations, members, keys. Content lives where it always did: one SQLite file per workspace, identical code hosted and local.
  • Workspace = Better Auth organization = one SQLite file. Members of the org are members of the vault. Q12 survives intact; "vault" becomes "workspace".
  • Multiplayer here is review, not cursors. Notion's multiplayer is co-editing. Washi has no cursor by design — the shared surface is one review queue over one agent's output.
  • CRDT merge is deferred, not deleted. One server means one replica means no divergence. Keep the sync-shaped data (HLC, tombstones, oplog); build the sync machinery when local mode returns.
00 · the trade

Local-first is suspended, and that has to be said out loud

Shipping hosted-first is a bet that you will do the hard thing later, with less energy and more constraints. The constraints in §02 are the collateral.

docs/features.md §2 lists "Local by default. No account, no cloud, no network unless explicitly allowed per site" under non-negotiable — a design that breaks one of these cannot ship. This document breaks it on purpose, for a stated reason: Washi is being built for team collaboration first.

That rule is suspended, with a return date (phase 7), not repealed. The difference between those two is entirely mechanical, and it lives in §02.

Three screens are now lying. apps/desktop/src/components/onboarding/OnboardingSteps.tsx promises "No account required" (l.28), "Washi never talks to a cloud we run" (l.162), and "nothing leaves this device until you say so" (l.81). It also promises "Markdown files in a folder you pick" and "one vault is one folder" — both already false today, since §04 is SQLite and Q6 defers file export. Onboarding is rewritten with a new design in phase 3, not patched.
What hosted-first buys, stated fairly
  • The hardest constraint first. Two clients against a remote server is strictly harder than one client against localhost. Satisfy it and embedded mode is a simplification, not a port.
  • P7 dies for free. Multi-tenancy is mandatory in hosted mode, so the module-singleton database handle is gone in phase 1 whether or not anyone plans it.
  • P3 and peer sync leave the critical path. One server, one replica, no divergence. The two hardest weeks in the old plan move to phase 8.
  • The Dashboard stops lying. "What happened while I was away" requires something to run while you are away. Nothing does today — the laptop closes and the agent dies.
  • Mobile becomes a client, not a port. §10's blocker was "the agent cannot run on-device". A server answers that without a second architecture.
01 · the four constraints

What keeps the door open

Hold all four and phase 7 is days. Break any one and local mode is never — it becomes a second implementation competing with every feature request.

C1 A workspace is a SQLite file, hosted too

rule
Postgres holds the control plane and nothing else. Zero sheet content, zero records, zero transcripts. A hosted workspace is a file on a volume.
breaks if
Content lands in Postgres rows keyed by org_id. Local mode then needs a second repository — two FTS engines, two JSON semantics, two transaction models — which is the same as never.
keeps
Q12 as decided. One repository implementation, forever.

C2 One binary, mode from the first commit

rule
mode: 'hosted' | 'embedded' exists and is asserted once at boot. Write the embedded branch as throw new Error('not yet') — but write it.
breaks if
Auth and tenancy decisions scatter as implicit truths ("there is always a JWT", "there is always an org") instead of routing through one switch point. Two auth modes discovered late is also the single most common place to ship an auth bypass.
shape
hosted requires JWT and refuses to boot without secrets; embedded binds 127.0.0.1 with a per-boot token. Never a per-request branch.

C3 repository and service never see the network

rule
They take a resolved workspace handle and an actor. No request, no session, no user lookup, no auth import, no Postgres import below the trpc layer.
breaks if
service imports Better Auth or reaches for the control plane. The one-way layering already forbids it; hosted mode is where that discipline gets tested for the first time.

C4 Desktop is the web client in a mirin window

rule
Same client code, different base URL. No native-only data paths, no desktop-only procedures.
breaks if
Desktop grows special cases early, and local mode becomes a third implementation rather than a redeployment of the second.
note
The whole renderer↔main coupling is one file today — apps/desktop/src/lib/rpc.ts, 19 call sites. This is the cheapest it will ever be.

Better name for the whole pivot: same binary, remote first. Local mode is a later deployment of code that already exists — not a later implementation.

Why tRPC and not Elysia + Eden (which §07 of v0.5 named)
  • The surface is already a procedure map. rpc.query / rpc.mutation over 18 flat methods is a tRPC router. Eden would force a resource layout onto something that is not resource-shaped.
  • Zod is the boundary rule; Elysia natively wants TypeBox — banned by the house conventions. tRPC's .input(schema) is that rule expressed by the framework rather than adapted against it.
  • createContext is where the workspace handle lives. The single biggest structural change in this pivot has an idiomatic home.
  • tracked() subscriptions resume. Four event streams (agent updates, approvals, open-sheet, and dataChanged from P1) survive a laptop lid closing with lastEventId instead of dropping transcript chunks. Free, and load-bearing once remote.

Where tRPC is the wrong tool: peer sync. Loro deltas are Uint8Array and superjson will base64 them — ~33% on every frame plus a JSON parse on the hot path. /sync is a plain binary WS mounted beside the tRPC handler on the same Bun.serve. Two protocols, one port, one process.

03 · two planes

Postgres never touches a sheet

This split is C1. Everything else in this document is recoverable; this one is the one-way door.

control plane · hosted only

Postgres + Better Auth

  • accounts, sessions
  • organizations, members, roles, invitations
  • workspace registry: id → file, org owner
  • BYOK key store (encrypted, write-only)
  • circuit-breaker state, share links
data plane · both modes, identical code

SQLite, one file per workspace

  • sheets, sheet_links, FTS5
  • user tables, records
  • agent sessions, turns, approvals
  • capability_calls ledger
  • oplog, app_meta

In embedded mode the control plane is replaced by a stub that answers "one local actor, one workspace, no auth". That substitution is the entirety of phase 7 — which is only true because C1 and C3 held.

Backups are per-file: periodic VACUUM INTO to object storage, keyed by workspace. A workspace is the natural backup, export and (later) sync unit — the same argument Q12 already made.

04 · workspace model

Organization = workspace = vault = one file

Washi's "vault" already means what Notion's "workspace" means. Use the word people arrive knowing.

Better AuthWashinotes

member + rolewho can open itowner / admin / member

Rename vault → workspace throughout. Q5 locked sheet · wsx · paper · ink · tsuru · hanko — "vault" was never in that list, so the rename costs nothing. The code is already ahead of the docs here: WorkspaceSwitcher.tsx and CreateWorkspaceDialog.tsx ship under that name today.

Multiplayer is review, not co-editing

The product bet is edit by asking — there is no cursor, on purpose. So the shared surface is not a document with three carets in it. It is one review queue over one agent's output: several humans deciding what the agent is allowed to have written.

Notion's multiplayer is cursors. Washi's multiplayer is a shared Inbox. Treat that as the differentiator, not the gap — and do not build presence.

Retrofit warning — the ledger needs an actor. capability_calls records origin ('agent' | 'sheet') but not who. With one user that was complete; with a team, "who approved this" is the entire audit story, and features.md already asks for "audit view of what was already approved or denied, and by whom". Add actor_id in phase 1. This is the HLC argument again: trivial now, brutal against a populated ledger.
05 · the agent, server-side

BYOK means you store the key

The Claude Agent SDK is a Bun process. It cannot run in a browser. "BYOK in the web client" therefore means the key is stored server-side and the server runs the agent with it. There is no version of this where it stays with the user.

Say it plainly in the UI too, because a user pasting a key into a web form deserves to know where it goes. What it obligates:

  • Encrypted at rest, write-only. Per-org data key derived from a server master key in env. Never readable back to any client — only ••••last4 and a Replace button.
  • An Anthropic key cannot be scoped. A leak is the user's entire Anthropic account, not just their workspace. Strictly worse than leaking a password: separate table, separate access path, every read audited.
  • Org-level key — the owner's key runs everyone's turns, Notion-style. No per-member keys in v1.
  • Prefer OAuth over paste if and when Anthropic offers it — a revocable grant beats a held credential. Support both; default to the grant.

Being OSS and self-hosted makes this much smaller than it sounds: you are not a key custodian. Each team holds its own keys in its own Postgres. The bar is "a database dump must not leak it", not "we operate an escrow". No KMS, no HSM, no vault service.

The circuit breaker — a safety stop, not a quota

No budgets, no seats, no plans: this is OSS and there is no pricing, now or later. But an agent loop on a shared org key, running scheduled overnight, is how a team wakes up to a drained account. That is not billing — that is a bug with a credit card attached.

One workspace-wide daily cap, sane default, prominent Resume button. And it needs the existing gap closed first: v0.5 §05 notes maxBudgetUsd is passed per query() call while the stored cost_usd is never enforced against — a papercut solo, an incident with someone else's key and a cron.

What moving the agent server-side unlocks

  • Scheduled runs — in features.md, impossible today: the agent dies with the lid.
  • An Inbox that fills overnight — the review queue is the product, and it currently only fills while you watch it.
  • A Dashboard that is not fiction.
06 · capabilities under a network boundary

Three gates, all of them now load-bearing

Loopback + token becomes network + real auth. The capability packages were designed for this — but two of them change shape, and one gets genuinely more dangerous.

tsuru SSRF stops being theoretical

was
A desktop process fetching a bad URL reaches the user's own LAN. Bad, contained.
now
A hosted server fetching user- and agent-supplied URLs sits inside your infrastructure, next to Postgres and the control plane. This is SSRF by construction.
owed
The private-range block must run post-DNS-resolution, not on the hostname. Hostname checks lose to DNS rebinding, and a rebind walks straight into the control plane. Pin the resolved address and connect to it.

hanko verbs split server / client

reality
The registry assumes the executor and the user share a machine. table.insert is a server verb. url.open and tab-opening are client verbs and cannot execute server-side at all.
fix
One annotation per verb. Client verbs return a stamped intent the client fulfills; the ledger row is still written server-side, by the server, with the actor.
keeps
Q13 intact — a click is consent for reversible in-vault verbs, never for anything leaving the machine. "The machine" just became "the user's machine", which is the honest reading.

ink unchanged, and that is the point

why
Descriptors are isomorphic and execution already lives in repository behind membership checks (P0). A network boundary in front changes nothing below it — which is the clearest evidence C3 is the right rule.

WSX stays inert data, and that carries over unchanged: a prompt-injected sheet on a shared workspace is still worst-case wrong content, never code execution. With multiple readers that property stops being a nicety and becomes the reason a shared workspace is safe at all.

07 · phases

Hosted first, local at 7

~7–8 weeks to a usable team product. Phases 7 and 8 are the deferred half, and they are only cheap if C1–C4 held the whole way.

  1. 1

    server + transport ~1w

    packages/desktop/* → packages/server/*; api → trpc in the conventions §3 shape. apps/server as a Bun binary with the mode flag present and the hosted branch live. Workspace handle resolved in createContext — P7 dies here. actor_id on the ledger. Deploy to Coolify on day one so it is never theoretical.

  2. 2

    auth + control plane ~1.5w

    Better Auth with the organization plugin, Postgres control plane, invitations, encrypted BYOK key store. docker-compose.yml as a first-class deliverable, not an afterthought — this is an OSS self-hosted product and the compose file is the install story.

  3. 3

    clients + new onboarding ~1.5w

    apps/web on TanStack Start; desktop repointed as a thin client (C4). Onboarding rewritten against a new design: sign in → create or join workspace → invite → BYOK → agent consent. The old local-first copy is deleted, not edited.

  4. 4

    agent server-side ~1w

    Agent host moves into the server. Circuit breaker + the per-session budget enforcement gap closed. Scheduled runs. The Inbox starts filling overnight, which is the first moment the product does something the desktop app could not.

  5. 5

    P2 · transactions + typed oplog ~4d

    Still required. A crash mid-write is worse with N users than with one. withTransaction, a typed Op union, ops as patches, readOps(sinceSeq). Acceptance unchanged from v0.5 §09: the oplog replays into an empty database and reproduces the workspace.

  6. 6

    M2.6 canvas sweep ~1w

    twMerge, strip L1/L2 chrome, de-cosmetic the primitives, fluid + container queries. Hard dependency: @washi/paper has zero responsive classes and hardcoded widths, so apps/web is desktop-width-only until this lands. Move it before phase 3 if the web client needs to be real sooner.

  7. 7

    embedded mode ~3–4d

    Flip C2's flag, stub the control plane, loopback token auth, desktop spawns the server as a sidecar. Three days if the constraints held. Otherwise this is the phase that never ships — which is the whole reason §01 exists.

  8. 8

    P3 + peer sync ~2w

    Only now does divergence exist. Stable peer id from device_id, delta log, version vectors, /sync binary WS. The server is a peer like any other — not a relay, not a merge brain, just another replica.

08 · decisions

Q20–Q28 — called 2026-09-16

Two diverge from the recommendation. Both are flagged on their cards, because a divergence you cannot find later is a decision you did not make.

Q20

Ordering

Local-first then hosted, or hosted then local? Team collaboration is the target use.

local-first first — it is the stated identity, and retrofitting it later historically never happens.

hosted first, local deferred to phase 7. (diverged) The tool is for team collaboration now; C1–C4 are the price of the deferral and are law, not guidance.

Q21

Hosted data plane

One SQLite file per workspace on a volume, or Postgres with org_id on every row?

SQLite per workspace — one repository implementation, and Q12 already chose file-per-vault.

SQLite file per workspace. Postgres is control plane only. This is C1.

Q22

Transport

tRPC + wsLink, or Elysia + Eden Treaty as v0.5 §07 named?

tRPC — the surface is already a procedure map, zod is native, and createContext houses the workspace handle.

tRPC v11. Peer sync stays off it: /sync is raw binary WS on the same port.

Q23

Workspace model

Does an organization hold many vaults, or is it one?

org == workspace == vault == one file. A second nesting level before there are two users is cost without use.

one org, one file. Better Auth teams skipped. vault renamed to workspace throughout.

Q24

BYOK custody

Key in the browser, or on the server? Org-level or per-member?

server-side, org-level. The SDK is a Bun process — browser-held keys make a server-side agent impossible, which deletes scheduled runs.

org-level, stored server-side, encrypted at rest, write-only to clients. OSS self-host means each team holds its own — not a custodial service.

Q25

Budgets

Per-member quotas, or none? There is no pricing and never will be.

no quotas — quotas are monetization machinery and this is OSS.

no quotas. One workspace-wide daily circuit breaker with a Resume button — a safety stop, not a tier. The per-session enforcement gap in §05 closes with it.

Q26

E2EE supersedes Q19

Does end-to-end encryption follow sync, as v0.5 decided?

closed as no. A server that runs the agent must read plaintext; "blind by construction" and "cloud agent" cannot both be true.

no E2EE. Private-mode workspaces become a question after phase 7, if ever. Ops keep their envelope shape — it costs nothing and keeps the option alive.

Q27

CRDT timing

One server means one replica. Is Loro still earning its place?

keep the format, defer the machinery. HLC, tombstones and oplog are the "cheap now, cursed to retrofit" set; delta export and version vectors are not.

Loro stays as the sheet storage format. P3 moves to phase 8 with sync.

Q28

Onboarding

Patch the local-first copy, or disable first-run until it is honest?

disable — shipping "no account required" over an account-gated app is a screenshot waiting to happen.

rewritten with a new design in phase 3. (diverged — went further than the rec.) The flow is different, not just the copy: sign in → workspace → invite → BYOK → agent consent.
