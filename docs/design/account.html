1 2
Proposed — no such tab exists; the three tabs are the whole rail and nothing renames, leaves or deletes a workspace. 1 Rename is one Better Auth call (organization.update); there is no icon field on purpose — the icon is topicFor(id), hashed from the id so two workspaces never match, and a picker would trade that for one more decision. 2 Delete is not: the organization row cascades in Postgres, but the SQLite file and its .claude/ session dir are the runtime's, so this needs a runtime procedure that closes the Workspace, deletes both and only then calls organization.delete. Owner-only, typed confirm.
Decided People are a projection, not a table. The workspace file holds member ids in person cells and comment rows; names come from Postgres at read time. Rename a user and every page follows; delete one and the id still points at a row that says who it was.
Open Roles exist (owner · admin · member) but nothing reads them past "can open". Removing a member and changing a role are one Better Auth call each; the question is what Washi should do with the person cells they leave behind.
